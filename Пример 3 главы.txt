3. ОПИСАНИЕ ПРАКТИЧЕСКОЙ РЕАЛИЗАЦИИ ИГРОВОГО ПРОГРАМНОГО ОБЕСПЕЧЕНИЯ НЕЙРОСЕТЕВОГО РАСПОЗНАВАНИЯ ЭМОЦИЙ
3.1 Структура разработанного программного обеспечения 
3.1.1 Модуль анализа эмоций
Модуль анализа эмоций должен обеспечивать распознавание эмоционального состояния пользователя в реальном времени через обработку видеопотока с веб-камеры [22]. Захват видео должен быть реализован с использованием OpenCV, где каждый кадр будет динамически масштабироваться до 50% исходного разрешения для оптимизации производительности. Детекция лиц должна выполняться SSD-моделью (Single Shot Detector), обеспечивающей баланс между скоростью и точностью. Для классификации эмоций задействована предобученная модель DeepFace, которая определяет шесть базовых эмоциональных состояний: гнев, страх, радость, грусть, удивление и нейтральность. Результаты анализа автоматически переводятся на русский язык через словарь emotion_translations, интегрированный в логику приложения.
Обработка данных выполняется асинхронно в отдельном потоке с использованием модуля threading, что предотвращает блокировку графического интерфейса. Для синхронизации видеопотока и отображения результатов задействована очередь frame_queue, ограниченная одним элементом для минимизации задержек [25]. Калибровка координат лица реализована через масштабирование области интереса (ROI) с учетом исходного разрешения кадра, что обеспечивает точное отображение рамки вокруг лица пользователя. При перегрузке системы модуль автоматически пропускает кадры, сохраняя стабильность работы даже на слабом оборудовании.
3.1.2 Модуль графического интерфейса
Графический интерфейс приложения «NeoFlex Emotion AI» реализован на базе библиотеки Tkinter, обеспечивающей кроссплатформенную работу на Windows и Linux [26]. Интерфейс сочетает видеопоток с веб-камеры, элементы управления и игровую логику в единой среде. Основное окно (1200×800 пикселей) включает видеопанель для отображения кадров с наложением HUD-элементов: рамок вокруг лиц, текстовых меток эмоций и таймеров. Панель управления содержит радиокнопки для выбора режимов («Дуэль», «Квест», «Удержание эмоции»), кнопки управления и статусную строку.
Интеграция OpenCV с Tkinter выполнена через преобразование кадров в формат ImageTk (библиотека Pillow), что позволяет отображать видео в реальном времени. Для предотвращения задержек GUI использована многопоточная архитектура: видеозахват, анализ эмоций и игровая логика работают в отдельных потоках, синхронизируемых через очередь (queue.Queue). Кастомизация стилей включает фирменную цветовую схему Neoflex (синие и оранжевые акценты), шрифты с поддержкой кириллицы (Arial, DejaVu Sans) и адаптивные кнопки с анимацией состояний.
Оптимизации интерфейса включают кэширование ресурсов (шрифты, изображения квестов), ленивую инициализацию окон (создаются только при активации режимов) и динамическую регулировку частоты кадров (15-30 FPS в зависимости от нагрузки). Для решения проблемы искажения кириллицы в OpenCV применен рендеринг текста через Pillow. Проблема утечек памяти устранена принудительным вызовом сборщика мусора после закрытия модальных окон.

Визуальные элементы HUD в приложении «NeoFlex Emotion AI» интегрированы в видеопоток для предоставления пользователю ключевой информации в реальном времени [24]. Их основная задача - обеспечить интуитивное взаимодействие без перекрытия основного контента [24]. 
•	Рамка обнаружения лица - динамически изменяющийся прямоугольник, выделяющий область лица в видеопотоке;

•	Индикаторы режимов - таймер обратного отсчета (в режимах «Максимум эмоций», «Дуэль»), cчетчики очков и раундов (в дуэли), прогресс-бар удержания эмоции;

3.1.3 Модуль игровых режимов
Модуль игровых режимов обеспечивает интерактивное взаимодействие с пользователем через пять специализированных сценариев, сочетающих элементы геймификации с технологиями компьютерного зрения. Архитектура модуля построена на принципах многопоточности: игровая логика выполняется в фоновых потоках, а обмен данными между компонентами осуществляется через очередь [38]. Это гарантирует отзывчивость интерфейса даже при высокой нагрузке. Интеграция с модулем анализа эмоций происходит через прямое чтение текущей эмоции, а калибровка координат лица обеспечивает точное отображение рамки вокруг области интереса. Модуль демонстрирует гибкость за счёт изолированной логики каждого режима, что упрощает добавление новых сценариев без изменения базовой архитектуры.
3.1.3.1 Режим «Максимум эмоций»
В режиме «Максимум эмоций» (Рисунок 21) пользователю необходимо продемонстрировать максимальное количество уникальных эмоций за 30 секунд. Система фиксирует каждую новую эмоцию через предобученную модель DeepFace, динамически подсвечивая индикаторы в интерфейсе [33]. Для отслеживания уникальных состояний используется фиксированное множество эмоций, зафиксированное в нижней части экрана, а асинхронный таймер, реализованный через встроенный в python модуль многопоточности, обеспечивает параллельное обновление графического интерфейса без задержек.

3.1.3.5 Режим «Эмоциональный квест»
Наиболее сложным сценарием является «Эмоциональный квест» (Рисунок 25), где прогресс зависит от демонстрации эмоций в соответствии с нелинейным сюжетом [35]. При запуске режима создаётся отдельное окно, с описанием сюжетной ситуации, а фоновый поток рекурсивно проверяет соответствие текущей эмоции условиям сцены [40].

3.1.4 Модуль управления ресурсами
Модуль управления ресурсами обеспечивает централизованную загрузку, кэширование и предоставление внешних данных для всех компонентов системы [37]. Основная функция модуля - работа с изображениями, шрифтами и конфигурационными файлами, используемыми в графическом интерфейсе и игровых сценариях. Загрузка ресурсов осуществляется через методы класса с обработкой платформозависимых путей: для корректной работы в Windows и Linux используется модуль os с автоматическим преобразованием разделителей директорий.
Изображения для квестовых сцен загружаются с помощью библиотеки PIL, масштабируются до разрешения 400×300 пикселей и кэшируются в памяти для быстрого доступа. При отсутствии файла активируется механизм обработки исключений: в интерфейс подгружается заглушка с текстовым описанием ошибки, что предотвращает аварийное завершение программы. Также через данный модуль загружаются шрифты для рендеринга текста в видеопотоке и в окне квеста с приоритетным выбором шрифта поддерживающим кириллицу. Если системный шрифт недоступен, модуль автоматически переключается на резервный вариант или стандартный шрифт PIL.
Для работы с путями используется динамическое определение директории исполняемого файла, что гарантирует корректное обнаружение ресурсов при запуске из разных локаций. Конфигурации игровых режимов (например, длительность раундов) хранятся в виде JSON-файлов и парсятся при инициализации приложения. Модуль интегрирован с сервисом многопоточности: загрузка тяжелых ресурсов (HD-изображений) выполняется в фоновом потоке, что исключает «зависание» интерфейса.
Ключевой особенностью является система перезагрузки ресурсов «на лету»: при изменении файлов в папке с ассетами во время работы программы модуль отслеживает модификации через хеширование и обновляет кэш без перезапуска приложения. Для оптимизации памяти используется слабые ссылки на редко используемые изображения, которые автоматически выгружаются при нехватке RAM. Взаимодействие с другими компонентами осуществляется через API-методы возвращающие готовые объекты для интеграции в GUI или игровую логику.
Пример обработки ошибок: при попытке загрузить несуществующее изображение для сцены квеста модуль возвращает стандартный объект  с надписью «Изображение недоступно», одновременно выводя предупреждение в консоль. Производительность загрузки ресурсов оптимизирована за счет предварительного кэширования - при старте приложения все обязательные файлы (шрифты, иконки, конфиги) загружаются однократно, а дополнительные ресурсы (изображения квеста) подгружаются по требованию.

3.4 Описание реализации модуля распознавания лиц
Модуль обработки видео обеспечивает захват и подготовку кадров с веб-камеры для последующего анализа эмоций. Реализация выполнена на базе библиотеки OpenCV, которая обеспечивает высокую производительность и поддержку работы в реальном времени. Основная функциональность модуля включает инициализацию камеры с автоматическим подбором разрешения (по умолчанию 640×480 пикселей), конвертацию цветового пространства из BGR в RGB для совместимости с графическим интерфейсом, а также масштабирование кадров до 50% исходного размера для оптимизации скорости обработки. Детекция лиц выполняется с использованием SSD-модели (Single Shot MultiBox Detector), которая возвращает координаты области лица и уровень уверенности. Для минимизации ложных срабатываний применяется пороговое значение confidence > 0.7.
Обработка видеопотока осуществляется в отдельном потоке для предотвращения блокировки графического интерфейса. Кадры передаются в очередь с ограниченным размером (максимум 1 элемент), что снижает задержки при синхронизации с модулем анализа эмоций. Интеграция с DeepFace выполняется через передачу области интереса (ROI) вокруг лица, что позволяет классифицировать эмоции с частотой 15–20 кадров/сек на CPU. Для оптимизации производительности используются методы уменьшения разрешения кадров, кэширование объектов OpenCV и гистограммная эквализация для улучшения качества изображения при слабом освещении.
Таким образом, модуль обеспечивает стабильную работу приложения в реальном времени, адаптируясь к условиям слабого освещения и сохраняя производительность даже на ограниченных аппаратных ресурсах. Выбор OpenCV вместо аналогов подтвердил свою эффективность в условиях требований проекта к скорости, точности и безопасности данных.
3.5 Описание реализации модуля распознавания эмоций
Модуль распознавания эмоций реализован с использованием библиотеки DeepFace, обеспечивающей классификацию эмоций на основе области лица, выделенной из видеопотока (Рисунок 30). Процесс начинается с детекции лица через SSD-модель OpenCV, которая определяет координаты области интереса с применением порога уверенности (confidence > 0.7) для фильтрации ложных срабатываний. Если лицо не обнаружено, система возвращает статус «Лицо не найдено» и переходит к следующему кадру.
Выделенная область лица масштабируется до разрешения 48×48 пикселей и нормализуется в диапазон [0, 1] для стабилизации работы нейросети. Предобработанные данные передаются в предобученную модель VGG-Face из DeepFace, которая возвращает распределение вероятностей по шести эмоциям: гнев, страх, радость, грусть, удивление, нейтральность. Доминирующая эмоция определяется через выбор максимальной вероятности. Результаты переводятся на русский язык с помощью словаря соответствий и передаются в графический интерфейс для отображения в HUD и обновления игровой логики.
Интеграция модуля в систему выполнена через многопоточную архитектуру: анализ выполняется в фоновом потоке, что предотвращает блокировку интерфейса. Координаты лица и результаты классификации синхронизируются через общие переменные и очередь сообщений. Обработка ошибок (например, временная потеря лица в кадре) реализована через механизм исключений и вывод предупреждений в статусную строку.
Для оптимизации производительности используется кэширование весов модели DeepFace при инициализации, что сокращает время обработки кадра.

3.6 Описание реализации взаимодействия модуля детекции лиц и модуля распознавания эмоций
Взаимодействие модуля (Рисунок 31) детекции лиц и модуля распознавания эмоций основано на передаче данных в формате массивов ndarray (NumPy), что обеспечивает эффективную обработку видеопотока в реальном времени. 3.7 Описание реализации модуля игровых режимов
Модуль игровых режимов обеспечивает интерактивное взаимодействие пользователя с системой анализа эмоций через пять уникальных сценариев. Каждый режим реализован с учетом асинхронной обработки видеопотока и динамического обновления интерфейса.
•	Режим «Максимум эмоций» (Рисунок 32) активирует 30-секундный таймер, в течение которого система фиксирует разнообразие демонстрируемых эмоций. Уникальные эмоции подсвечиваются на панели индикаторов в реальном времени. По истечении времени выводится итоговое количество распознанных эмоций.
 
Рисунок 32 – Демонстрация режима «Максимум эмоций»
•	Режим «Имитации эмоций» случайным образом выбирает целевую эмоцию из предустановленного списка. Пользователю дается три попытки по 10 секунд для демонстрации требуемой реакции. Система фиксирует успешные совпадения и автоматически генерирует новую цель при правильном ответе. Результат отображается как соотношение успешных попыток к общему числу раундов.
•	Режим «Удержания эмоции» включает диалоговое окно для выбора целевой эмоции. После старта обратного отсчета система измеряет продолжительность непрерывного воспроизведения выбранной реакции. Таймер останавливается при изменении эмоции или завершении игры, отображая достигнутое время удержания и исторический рекорд сессии.
•	Режим «Дуэль» организует соревнование между двумя игроками через три раунда. Каждому раунду соответствует случайно выбранная эмоция, которую поочередно демонстрируют участники. Система присваивает очки за успешное распознавание в течение 10 секунд, обновляя счетчик раундов и отображая активного игрока. Итог подводится на основе сравнения результатов участников с возможностью ничьей.
•	«Эмоциональный квест» (Рисунок 33) реализует сюжетный сценарий с нелинейным развитием. Каждая сцена содержит уникальный текст, фоновое изображение и набор эмоций для перехода на следующий этап. Система отслеживает соответствие текущей эмоции требованиям сцены, автоматически активируя переход при успешном распознавании. Визуальная часть квеста отображается в отдельном окне с динамическим обновлением контента.
